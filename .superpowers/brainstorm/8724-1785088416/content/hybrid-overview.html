Hybrid Interaction Paradigm

Three modes, one unified interface — recruiter chooses how to work

The Core Idea

The three paradigms aren't mutually exclusive — they're views into the same data. The hybrid gives recruiters interaction choice without context-switching cost.

1

Primary: Activity Feed

Chronological timeline of agent suggestions, recruiter actions, and system events. The default view. Agent posts candidate matches, insights, and learning digests. Recruiter acts inline.

Best for: daily workflow, agent interaction, multi-job awareness
2

Tab: Pipeline / Kanban

Job-scoped visual pipeline: Sourced → Reviewing → Submitted → Interviewing → Placed. Accessible via tab or per-job link from feed items. Drag-and-drop stage transitions. Agent suggests moves.

Best for: bottleneck spotting, stage management, AM oversight
3

Overlay: Command Bar

⌘K accessible from any view. Natural language or slash commands: /find candidates for TCS Java, /submit Jane Doe to Wipro PM, what's my pipeline look like?. Results inline or navigate to relevant view.

Best for: power users, bulk ops, quick actions without leaving flow

How They Connect

From Feed → Pipeline
Click any candidate card or "View Pipeline" on a job card → opens Pipeline tab scoped to that job
From Pipeline → Command
⌘K while in Pipeline view. "submit selected", "schedule interview for Alice" → overlays command without leaving context
From Command → Feed
Command results post into the feed as a new entry. "Found 12 candidates for TCS Java" appears as a feed item with candidate cards

Navigation Model

📋 Feed → 📊 Pipeline → 🏢 Jobs → ⚙️ Preferences → 📈 Analytics

Top-level tab bar + persistent ⌘K. No sidebars — maximize content space. Command bar is modeless (doesn't block the view).

Strengths

  • Recruiter chooses the right tool for the task
  • Agent feels like a collaborator, not a chatbot
  • Pipeline visibility without losing agent context
  • Power users can live in command bar; new users start in feed

Risks

  • More UI to build and maintain
  • Risk of "which view should I use?" confusion
  • Feed could feel redundant with pipeline notifications
  • State sync between views must be seamless
